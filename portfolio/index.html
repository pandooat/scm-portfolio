Analysis Summary

5 Key Findings

What the simulated data reveals about supply chain failure patterns

01

Supplier Reliability is the Primary Bottleneck

At 35.95% OTD, only 1 in 3 purchase orders arrives on time. Fast-moving SKUs with unreliable suppliers consistently appear in both high-stockout-day and high-unserved-value rankings — the strongest upstream signal in the dataset.

02

OTIF Failure is Dual-Cause, Not Single-Cause

19% of orders (942 total) fail both completeness and timing simultaneously — compounded failures requiring concurrent supply and delivery interventions. Treating this as a single-dimension problem will underperform.

03

Stockout Risk is Concentrated, Not Universal

70 of 144 SKU-warehouse combinations are below the 95% service level reorder threshold. The top 20 by Unserved Order Value account for a disproportionate share — targeted action outperforms blanket safety stock increases by a wide margin.

04

ABC Classification Reveals Misaligned Priorities

Class A SKUs (top 80% revenue) must be protected with higher service level targets and tighter reorder cycles. Class C items can sustain leaner replenishment policies — inventory policy differentiation by class is the highest-ROI structural fix.

05

Turnover Trend Reveals Maldistribution

Inventory Turnover analysis combined with stockout data shows some SKU-warehouse combinations hold excess stock while fast movers stock out. This is a distribution and replenishment timing problem as much as a volume problem.

-- Q01: SKU count per product category
SELECT
    category,
    COUNT(*) AS sku_count
FROM dim_products
GROUP BY category
ORDER BY sku_count DESC, category;
Context Portfolio spans Food, Personal Care, Home Care, Beverage — guides priority-setting for safety stock and demand planning complexity.
sqlite3 · query_05_fill_rate_warehouse.sql 
-- Q05: Fill rate by warehouse (units fulfilled / units ordered)
SELECT
    w.warehouse_name,
    SUM(s.ordered_qty)   AS units_requested,
    SUM(s.fulfilled_qty) AS units_fulfilled,
    ROUND(100.0 * SUM(s.fulfilled_qty)
        / NULLIF(SUM(s.ordered_qty), 0), 2) AS fill_rate_pct
FROM fact_sales_order_lines s
JOIN dim_warehouses w ON s.warehouse_id = w.warehouse_id
GROUP BY w.warehouse_name
ORDER BY fill_rate_pct;
Context Warehouse-level fill rate isolates whether the fulfillment problem is structural (all locations underperform) or location-specific — determines intervention scope.
sqlite3 · query_08_otif_warehouse.sql 
-- Q08: OTIF rate per warehouse (order grain, not line grain)
SELECT
    w.warehouse_name,
    COUNT(*)           AS total_orders,
    SUM(s.otif_flag)   AS otif_orders,
    ROUND(100.0 * SUM(s.otif_flag) / COUNT(*), 2) AS otif_pct
FROM fact_shipments s
JOIN dim_warehouses w ON s.warehouse_id = w.warehouse_id
GROUP BY w.warehouse_name
ORDER BY otif_pct;
Context OTIF is measured at order grain (1 order = 1 row in fact_shipments). Averaging line-level metrics would dilute the KPI — this query uses the correct denominator.
sqlite3 · query_10_supplier_otd.sql 
-- Q10: Supplier OTD for received POs only
SELECT
    sup.supplier_name,
    COUNT(*) AS received_po,
    SUM(CASE WHEN po.actual_receipt_date <= po.expected_date
             THEN 1 ELSE 0 END) AS on_time_po,
    ROUND(100.0 *
        SUM(CASE WHEN po.actual_receipt_date <= po.expected_date
                 THEN 1 ELSE 0 END) / COUNT(*), 2) AS supplier_otd_pct,
    ROUND(AVG(julianday(po.actual_receipt_date)
            - julianday(po.order_date)), 1) AS avg_lead_time_days
FROM fact_purchase_order_lines po
JOIN dim_suppliers sup ON sup.supplier_id = po.supplier_id
WHERE po.actual_receipt_date IS NOT NULL
GROUP BY sup.supplier_id
ORDER BY supplier_otd_pct;
Context WHERE filters to received POs only — open POs are excluded from denominator to avoid penalizing future performance. Reported separately.
sqlite3 · query_13_abc_classification.sql 
-- Q13: ABC classification using window function
WITH sku_sales AS (
    SELECT product_id, SUM(revenue) AS revenue_rp
    FROM fact_sales_order_lines
    GROUP BY product_id
),
ranking AS (
    SELECT product_id, revenue_rp,
        SUM(revenue_rp) OVER (
            ORDER BY revenue_rp DESC, product_id
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) AS cumulative_revenue_rp,
        SUM(revenue_rp) OVER () AS grand_total_rp
    FROM sku_sales
)
SELECT
    p.sku, p.product_name, r.revenue_rp,
    ROUND(100.0 * r.cumulative_revenue_rp / r.grand_total_rp, 1) AS cumulative_pct,
    CASE
        WHEN 1.0 * r.cumulative_revenue_rp / r.grand_total_rp <= 0.80 THEN 'A'
        WHEN 1.0 * r.cumulative_revenue_rp / r.grand_total_rp <= 0.95 THEN 'B'
        ELSE 'C'
    END AS abc_class
FROM ranking r
JOIN dim_products p ON p.product_id = r.product_id
ORDER BY r.revenue_rp DESC;
Context Window function computes cumulative revenue share without a self-join. ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW ensures exact boundary handling for SKUs at the 80%/95% thresholds.
sqlite3 · query_15_inventory_turnover.sql 
-- Q15: Monthly inventory turnover using daily average method
WITH daily_inventory AS (
    SELECT substr(snapshot_date, 1, 7) AS ym,
           snapshot_date,
           SUM(inventory_value) AS daily_inventory_value
    FROM fact_inventory_daily
    GROUP BY ym, snapshot_date
),
monthly_avg AS (
    SELECT ym, AVG(daily_inventory_value) AS avg_inventory_value
    FROM daily_inventory GROUP BY ym
),
monthly_cogs AS (
    SELECT substr(order_date, 1, 7) AS ym, SUM(cogs) AS cogs_rp
    FROM fact_sales_order_lines GROUP BY ym
)
SELECT
    m.ym,
    ROUND(m.avg_inventory_value, 0) AS avg_inventory_rp,
    c.cogs_rp,
    ROUND(1.0 * c.cogs_rp
        / NULLIF(m.avg_inventory_value, 0), 3) AS inventory_turnover_in_month
FROM monthly_avg m
JOIN monthly_cogs c ON c.ym = m.ym
ORDER BY m.ym;
Context Daily average method (avg across all snapshot days per month) is more accurate than simple beginning/end average. Result is period turnover — not annualized — to avoid overstating efficiency.

Supply Chain Math & Formula Definitions

1. Dynamic Reorder Point (ROP) with Joint Uncertainty

Accounts for both daily sales volatility and supplier delivery variance without assuming zero lead-time standard deviation:

Safety Stock (SS) = Z × √(L_mean × σ_Demand² + Demand_mean² × σ_LeadTime²)
Reorder Point (ROP) = ⌈Demand_mean × L_mean + Safety Stock⌉

2. OTIF (On-Time In-Full) Strict B2B Definition

A customer order is only counted as successful if 100% of requested units are fulfilled AND delivered on or before the promised delivery date:

OTIF Flag = 1 IF (shipped_qty == ordered_qty AND delivered_date <= promised_date) ELSE 0
OTIF % = ∑(OTIF_Flag) / Total Sales Orders (Order grain, not line grain)

3. WAPE (Weighted Absolute Percentage Error)

Used for intermittent FMCG demand backtesting to prevent division-by-zero errors inherent in traditional MAPE:

WAPE = (∑ |Actual_t - Forecast_t|) / (∑ Actual_t)
